# Privacy, Localization and Daily Utility — الموجة الثالثة (2026-10-21)

الخصوصية أوضح، الاتجاهان أصحّ، والاستعمال اليومي أسرع — بدون لمس الشات أو الـAI، وبدون أي تغيير سكيمة أو RLS.

- **الفرع:** `feature/privacy-localization-utility` — **مبني فوق `feature/spaces-family-ux`** (الموجة الثانية، PR #110 ← #109). الـPR قاعدته فرع الموجة الثانية، فالـdiff يعرض تغييرات هذه الموجة فقط؛ تُعاد تتبّع القواعد مع كل دمج.
- **الحالة:** منفّذة بالكود + اختبارات خضراء محلياً — بانتظار مراجعة المالك والدمج. لم تُنشر OTA.

## مراجعة الخصوصية والخزنة (ما انفحص، وما تبيّن)

- **المساحة الخاصة والخزنة**: الخزنة طبقة فوق المساحة الخاصة — مفاتيح بالذاكرة فقط، الجلسة بتنقفل وبتتمسح بصماتها عند الخروج (اتقوّى بالموجة الأولى)، ورسالة «مش موجودة أصلاً» للخزنة الوهمية/الخاطئة (ثبات مقصود ضد التخمين). لا كلمات سر أو مفاتيح حساسة بـ AsyncStorage كنص صريح من كود التطبيق — جلسة Supabase نفسها بإدارة مكتبة Supabase (قرار SecureStore = D2 عند المالك، بناء native، خارج هذه الموجة).
- **Face ID / القفل البيومتري: غير منفّذ — بقصد.** `expo-local-authentication` **مش مثبّتة** بالمشروع، وإضافتها تعني **بناء native جديد (EAS)** — مش OTA. حسب التعليمات: وثّق ولا تعمل workaround مش آمن. المتطلب الكامل عند التنفيذ: تثبيت الحزمة + إعادة بناء + بوابة فتح خزنة/تطبيق عند الاستئناف + fallback برمز/كلمة سر الخزنة الحالية + اختبار جهاز حقيقي. اختبار حراسة بهذه الموجة بيمنع إدخال الاعتماد أو استيراده خلسة.
- **تصدير/حذف الحساب**: موجودان أصلاً بقسم «الخصوصية وبياناتي» — تصدير JSON كامل، وحذف نهائي بخطوتين مكتوبتين + حارس انشغال. ما اتغيّر فيهم شي.
- **الان降级/انتهاء الاشتراك لا يمسح بيانات**: حدود المساحات المخصصة بتقفل الإنشاء الزائد فقط؛ الموجود بيضل شغال وقابل للقراءة (سلوك `manage-space` + CFP-01 الموثّق). لا يوجد أي مسار حذف مرتبط بانتهاء خطة.
- **RLS**: هذه الموجة لا تمس أي سياسة أو سكيمة — التغييرات كلها عميل + خيار فلتر قراءة بالمحرّك (`listTasks` status) بيمرّ بنفس RLS القائم.

## المشكلة القديمة وسببها

1. **المواعيد المتأخرة غير مميّزة**: سطر التاريخ بالأجندة نص عادي — المتأخر مثل القادم. منطق التأخير كان موجود بس داخل ملخص الشات الصباحي.
2. **لا فلتر حالة للمهام**: تبويب مهام العائلة بيعرض الكل مخلوطاً (الخادم مرتب الحالة أصلاً، بس بلا فلتر).
3. **لا فلتر للأغراض المستعارة**: الاستعارة بادج على الصف، بلا طريقة لعرض المستعار فقط.
4. **نتائج البحث عبر المساحات بلا مؤشّر مصدر**: البحث بيجيب من كل المساحات، والصف ما بيقول النتيجة من أي مساحة — الخاص والمشترك شكلهما واحد، وهيدا فجوة خصوصية عرضية (مش تسريب بيانات: RLS سليم، بس المستخدم ما بيمّيز).

## التغيير الذي تم

- **`lib/due.ts`** (جديد، نقي ومختبَر): `dueState` بيصنّف overdue/today/upcoming بحدود **يوم الجهاز المحلي** (مش UTC) — موعد 9 صباحاً ما بيصير «متأخر» بسبب فرق توقيت؛ المنجزة أبداً مش متأخرة؛ التاريخ الناقص/الفاسد = null.
- **الأجندة**: سطر الاستحقاق بيتلون بالأحمر + وسم «متأخر» ⚠️ للمتأخر، ووسم «اليوم» لليوم — بمفاتيح i18n بالعربي والإنجليزي.
- **فلتر مهام خادمي**: `listTasks` صار بيحترم `PageOpts.status` (`.eq('status', …)`) — شرائح الكل/مفتوحة/منجزة بتبويب مهام العائلة بتحدّث بالفلتر من الخادم فالترقيم بيضل صادق تحت الفلتر. الفلتر بيتصفّر عند تبديل المساحة المعروضة (المحمّلات بتنعاد بلا فلتر عند الفتح — فالشريحة ما بتكذب).
- **فلتر «المستعارة فقط»** بقائمة أشيائي (عميل، فوق الصفحات المحمّلة، من `borrowFor` القائم) + حالة فراغ مخصصة؛ بيتصفّر مع تبديل المساحة كمان.
- **مؤشرات خصوصية على نتائج البحث**: مساعد واحد `spaceChipFor` — صفوف نتائج بحث الملاحظات والأشياء صارت تحمل شارة مساحتها الأم: 🔒 خاص / 👥 عائلة / 💼 عمل / 🗂️ مخصص + اسم المساحة المترجم.

## التذكيرات — حالة migration 0020 (موثّقة ومتحقّق منها حيّاً)

- الملف `supabase/migrations/0020_reminders.sql` موجود بالمستودع: pg_cron كل 15 دقيقة (`send_due_reminders`)، المواعيد قبل ساعة، المهام عند الاستحقاق، التاريخ بلا وقت = 9:00 صباحاً America/New_York، تذكير واحد لكل عنصر (`reminder_sent_at` + trigger إعادة تسليح)، والإرسال عبر pg_net لواجهة Expo Push.
- **تصحيح للسجل**: سطور ROADMAP القديمة («باقي تشغيل 0020» و«0021/0022 بانتظار تشغيل المستخدم») **قديمة وغير صحيحة اليوم** — تحقق حي للقراءة فقط بتاريخ 2026-10-21: على **Scratch والإنتاج معاً**، وظيفتا `mawjood-due-reminders` و`mawjood-watch-reminders` موجودتان ومجدولتان `*/15 * * * *` وفعّالتان، وعمود `items.reminder_sent_at` موجود، وقيد `items_kind_check` على الإنتاج يشمل `expense` (0021) و`watch` (0022) — أي إن **0020 و0021 و0022 مطبّقة فعلياً بالبيئتين**. (صحّحت سطور ROADMAP بهذا الـPR.)
- **اللي لسا ناقص للوصول الفعلي للهواتف**: الإشعارات بتوصل بس من تطبيق native (EAS) مسجّل رموز أجهزة حقيقية — حسب ملاحظة الـmigration نفسها. البنية الخادمية حية؛ إثبات الوصول end-to-end بيحتاج جهازاً حقيقياً ببناء EAS وتوكن مسجّل — لم يُدّعَ بهذه الموجة.
- **Fallback داخل التطبيق** عند غياب الـpush: الأجندة مع تمييز المتأخر/اليوم (هذه الموجة) + شريط الأسبوع + الملخص الصباحي القائم.
- **مواعيد الجهاز (device calendar)**: تصدير لموعد لتقويم الجهاز بيحتاج حزمة native (`expo-calendar`) — تصميم فقط: زر «أضف للتقويم» بصف الموعد بيستدعي إذن تقويم + إنشاء حدث من `due_at`/العنوان؛ غير منفّذ لنفس سبب Face ID (native)، وموثّق هنا بدل بنائه ناقصاً.

## خطوات التحقق على iPhone

1. اعمل مهمة/موعد بتاريخ مبارح من الشات وافتح الأجندة → سطرها أحمر مع «متأخر»؛ وموعد اليوم عليه «اليوم».
2. بمهام العائلة: بدّل الكل/مفتوحة/منجزة → القوائم بتتفلتر من الخادم و«حمّل المزيد» بيكمل بنفس الفلتر؛ بدّل المساحة → الفلتر بيرجع «الكل».
3. بأشيائي: فعّل «المستعارة» → بس المستعار بيظهر؛ وبلا مستعار بتظهر حالة الفراغ المخصصة.
4. ابحث عبر المساحات بكلمة موجودة بالخاص وبالعائلة → كل نتيجة شايلة شارة مساحتها (🔒/👥).
5. بالعربي والإنجليزي: راجع صفوف البحث والشارات والأسطر المميزة — لا قصّ ولا انكسار اتجاه.
